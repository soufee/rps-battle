# План перехода на кроссплатформенный React Native (iOS, Android, Web)

В данном документе представлен пошаговый план миграции игры **RPS Battle** на стек **React Native + Web** с внедрением базы данных, новой системы авторизации и социального взаимодействия.

---

## Архитектура системы

```
+-------------------------------------------------------------------------+
| Клиентская часть                                                        |
|  - Web Client (React Native for Web)                                    |
|  - Android App (React Native) / iOS App (React Native)                  |
|  - VK Mini Apps / Facebook Instant Games (Iframe Web View)              |
+------------------------------------┬------------------------------------+
                                     │ (HTTPS / WebSockets + JWT)
                                     ▼
+-------------------------------------------------------------------------+
| Серверная часть (Node.js Express + Socket.IO)                           |
|  - Валидация подписей VK/FB, выдача JWT                                 |
|  - Ролевой доступ (Игрок / Администратор)                               |
+--------------------┬----------------------------┬-----------------------+
                     │                            │
                     ▼                            ▼
+-----------------------------+         +---------------------------------+
| База Данных MySQL           |         | Redis                           |
| - Добавлены поля бана и роли|         | - Активные игровые комнаты      |
| - Связка соцсетей           |         | - Кэш онлайн-статусов           |
+-----------------------------+         +---------------------------------+
```

## Шаг 1. Настройка сервера и Базы Данных (MySQL + Redis)

> [!IMPORTANT]
> Для стабильности данных все СУБД упаковываются в Docker-контейнеры с привязкой постоянных томов на жесткий диск сервера.

1. **Установка Docker на сервере:**
   ```bash
   apt-get update
   apt-get install -y docker.io docker-compose-v2
   systemctl enable --now docker
   ```
2. **Создание `docker-compose.yml` для БД:**
   Создается стек из MySQL 8.0 и Redis для оптимизации работы комнат:
   * **MySQL:** Хранит профили, историю матчей, список друзей.
   * **Redis:** Хранит активные комнаты Socket.IO для быстрого отклика и возможности масштабирования.
3. **Проектирование схемы БД (MySQL):**
   * **Таблица `users`:** `id`, `email`, `nickname`, `avatar_url`, `created_at`.
     * *Новые поля:* `role` (ENUM: 'player', 'admin'), `platform` (ENUM: 'web', 'android', 'ios', 'vk', 'facebook'), `external_id` (ID в соцсети), `is_banned` (BOOLEAN), `banned_reason` (TEXT), `banned_until` (DATETIME).
   * **Таблица `stats`:** `user_id`, `wins`, `losses`, `draws`, `rating_mmr`.
   * **Таблица `friends`:** `user_id_1`, `user_id_2`, `status` (PENDING, ACCEPTED, BLOCKED).
   * **Таблица `match_history`:** `id`, `player_1_id`, `player_2_id`, `winner_id`, `score`, `played_at`.
4. **Настройка ежедневного бэкапа:**
   * Установка `rclone` и интеграция с Google Диском.
   * Добавление скрипта бэкапа в `/root/backup.sh` и настройка планировщика `cron` на 03:00 ежедневно.

## Шаг 2. Обновление серверного API и авторизации (JWT)

1. **Отказ от сессионных кук:**
   Переход с `express-session` на **JWT (JSON Web Tokens)**. При успешном входе сервер выдает клиенту `accessToken` (живет 1 час) и `refreshToken` (живет 30 дней).
2. **Реализация OAuth для мобильных клиентов:**
   * Добавление эндпоинта `POST /api/auth/google-native`. Он принимает `idToken` от Android/iOS приложения, валидирует его через Google Auth Library и выдает JWT игры.
   * Добавление эндпоинта `POST /api/auth/apple` (обязательно для публикации в App Store, если есть сторонний вход вроде Google).
3. **Обновление сокетов (Socket.IO):**
   * Изменение middleware авторизации сокетов. Теперь сокет считывает токен из `socket.handshake.auth.token`.
   * Блокировка соединений для забаненных пользователей: если у пользователя в БД стоит флаг `is_banned=true` и срок бана не истек, сокет отключается.

## Шаг 3. Игровые и социальные фичи (Бэкенд)

### 1. Сохранение статистики матчей
* По окончании игры в `online-rooms.js` сервер отправляет SQL-запрос для записи результата в `match_history`.
* Автоматически обновляется рейтинг ELO/MMR игроков в таблице `stats` (+/- 25 очков за победу/поражение).

### 2. Система друзей (Friends API)
* `POST /api/friends/request` — отправить запрос в друзья по никнейму/ID.
* `POST /api/friends/accept` — принять запрос.
* `GET /api/friends/list` — получить список друзей со статусом их онлайна (онлайн-статус берется из Redis на основе активных подключений в Socket.IO).

### 3. Приглашение друзей (Lobby Invites)
* При создании приватной комнаты генерируется уникальный короткий код (например, `678-234`).
* Добавление эндпоинта `POST /api/lobby/invite`, отправляющего Push-уведомление другу (через Firebase Cloud Messaging) с предложением войти в игру.
* Поддержка **Deep Linking (Глубоких ссылок):** ссылка формата `https://rps-battles.com/join/678-234` при клике на телефоне автоматически открывает приложение RPS и подключает игрока в нужное лобби.

## Шаг 4. Разработка клиента (React Native + Web)

> [!TIP]
> Для организации проекта лучше всего использовать **Expo (Bare Workflow)**. Он значительно упрощает сборку под iOS/Android, поддерживает Web из коробки и упрощает интеграцию нативных функций.

### 1. Структура проекта (Монорепозиторий или общая папка)
* Выносим всю логику подсчета ходов, ИИ-стратегий и сетевых запросов в отдельную папку `shared/` (чистый JS/TS).
* Компоненты UI пишем на React Native.

### 2. Верстка UI и Анимации:
* **Анимации:** Использование библиотеки `react-native-reanimated` для плавной отрисовки движения фигур на сетке.
* **Сетка поля боя:** Верстается с использованием Flexbox в React Native (который на вебе транслируется в стандартные CSS-стили).
* **Стили:** Использование `StyleSheet.create` гарантирует одинаковый рендеринг на мобильных устройствах и в браузере.

### 3. Реализация шаринга (Делиться результатами):
* Использование нативного API обмена:
  ```javascript
  import { Share } from 'react-native';

  const shareResults = async (score) => {
    try {
      await Share.share({
        message: `Я выиграл в RPS Battle со счетом ${score}! Сможешь победить меня? Сыграй со мной: https://rps-battles.com/`,
      });
    } catch (error) {
      console.log(error.message);
    }
  };
  ```
  *На мобильных устройствах это откроет системную шторку (Telegram, WhatsApp, Twitter, Instagram Stories), а в браузере задействует Web Share API или скопирует ссылку в буфер обмена.*

## Шаг 5. Интеграция с VK Mini Apps и Facebook Instant Games

Платформы мини-игр работают внутри Iframe веб-версии, используя JS SDK платформ для авторизации и интеграции.

### 1. Авторизация на платформах:
* **VK Mini Apps:** На клиенте вызывается `bridge.send("VKWebAppGetUserInfo")` для получения профиля. Параметры запуска (query-строка с подписью `sign`) передаются на сервер. Сервер валидирует подпись по секретному ключу приложения VK, регистрирует пользователя и выдает JWT.
* **Facebook Instant Games:** Используется `FBInstant.initializeAsync()`. Клиент передает серверу зашифрованную подпись игрока (`FBInstant.player.getSignedPlayerInfoAsync`), сервер декодирует её с помощью App Secret, валидируя игрока.

### 2. Особенности API:
* Автоматическая подгрузка списка друзей, которые уже установили приложение (через SDK VK/FB).
* Отправка сообщений-вызовов напрямую в диалоги (VK Bridge `VKWebAppShowInviteBox` / FB `FBInstant.context.chooseAsync`).

## Шаг 6. Интеграция рекламы (Ad Monetization)

Для монетизации на разных платформах используются разные SDK-агрегаторы.

1. **Мобильные приложения (iOS/Android):**
   * Интеграция `react-native-google-mobile-ads` (Google AdMob) или Yandex Mobile Ads SDK.
   * **Баннеры (Banner Ads):** Внизу экрана лобби.
   * **Межстраничная реклама (Interstitial Ads):** Показывается между матчами (не чаще одного раза в 3-4 игры, чтобы не раздражать пользователей).
   * **Вознаграждаемая реклама (Rewarded Ads):** Просмотр ролика для получения бесплатных бонусов (например, дополнительных косметических скинов для фигур).
2. **VK Mini Apps & Facebook Instant Games:**
   * **VK:** Интеграция показа рекламы через VK Bridge:
     * Межстраничная: `bridge.send("VKWebAppShowInterstitialAd")`.
     * Вознаграждаемая: `bridge.send("VKWebAppShowRewardedAd")`.
   * **Facebook:** Использование встроенного SDK `FBInstant.getRewardedVideoAsync()` и `FBInstant.getInterstitialAdAsync()`.

## Шаг 7. Панель администратора (Admin Dashboard & Модерация)

Для контроля над игрой создается административная панель. Доступ к ней открыт только пользователям с `role = 'admin'`.

### 1. Серверная часть (Admin API):
* `GET /api/admin/users` — поиск пользователей по никнейму/ID/почте с пагинацией.
* `POST /api/admin/users/:id/ban` — блокировка пользователя (принимает `reason` и `until` — дату окончания бана). При бане сессия пользователя инвалидируется, а сокет обрывается.
* `POST /api/admin/users/:id/unban` — разблокировка.
* `GET /api/admin/analytics` — сводная статистика:
  * Число активных игроков (DAU/MAU).
  * Количество созданных матчей за день/неделю.
  * Общая статистика побед/поражений и ELO-распределение.
  * Статистика просмотров рекламы.

### 2. Клиентская часть (Admin UI):
* Раздел администратора доступен по ссылке `https://rps-battles.com/admin` (только для веба во избежание захламления мобильного приложения, либо как скрытый экран в приложении для аккаунтов администраторов).
* Простой дашборд с графиками активности (например, на основе Chart.js или Recharts) и удобной таблицей пользователей с кнопками "Забанить" / "Разбанить" и формой ввода причины бана.
