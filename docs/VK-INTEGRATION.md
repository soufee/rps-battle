# Интеграция RPS Battle в VK (VK Mini Apps / Игры ВКонтакте)

Игра полностью готова к подключению со стороны кода и сервера. Всё, что осталось, —
завести приложение на [dev.vk.com](https://dev.vk.com) и вписать два значения в
`backend/.env`. Ниже — пошаговая инструкция и чек-лист модерации.

---

## Шаг 1. Создать приложение

1. Зайдите на [dev.vk.com](https://dev.vk.com) под своим аккаунтом VK.
2. «Мои приложения» → **«Создать приложение»**.
3. Тип — **Мини-приложение (VK Mini Apps)**, категория — **«Игры»**
   (так игра попадёт в каталог Игр ВКонтакте; названия пунктов в консоли VK
   периодически меняются — суть: встраиваемое iframe-приложение, а не Standalone).
4. Название: **RPS Battle** (или своё).

## Шаг 2. Настройки приложения

В разделе «Настройки» укажите:

- **Адрес iframe / URL приложения**: `https://rps-battles.com/`
- **Мобильный адрес** (m.vk.com и приложения VK): тот же `https://rps-battles.com/`
- Состояние: для начала — «Приложение отключено / видно только разработчикам»,
  чтобы спокойно протестировать.

Там же возьмите два значения:

- **ID приложения** (число, видно в URL и в настройках);
- **Защищённый ключ** (Secure key / «секретный ключ»). ⚠️ Не путайте с
  «Сервисным ключом доступа» — нужен именно **защищённый** ключ: им VK
  подписывает параметры запуска.

## Шаг 3. Вписать ключи на сервере

На сервере:

```bash
nano /root/www/backend/.env
```

Добавьте/заполните строки:

```
VK_APP_SECRET=<Защищённый ключ из шага 2>
VK_APP_ID=<ID приложения из шага 2>
```

Перезапустите бэкенд:

```bash
systemctl restart rps-v2-backend
```

⚠️ Пока `VK_APP_SECRET` пуст, вход из VK работает, но подпись не проверяется
(её можно подделать). Перед публикацией ключ должен быть задан обязательно.

## Шаг 4. Проверка

1. Откройте `https://vk.com/app<ID_приложения>` (или через «Управление» → «Открыть»).
2. Игра должна открыться в iframe и **сразу залогинить вас как VK-игрока** —
   без экрана входа: ник вида `Имя_Фамилия_xxxxxx`, лобби с режимами
   «Быстрая игра / Арена / Боты».
3. Проверьте партию с ботом и быструю игру.
4. Проверьте с телефона в приложении VK (мобильный webview).

Если что-то не так — см. «Диагностика» внизу.

## Шаг 5. Карточка приложения и модерация

Для публикации в каталоге заполните в консоли VK:

- **Иконка** 1024×1024 — можно взять `client/assets/icon.png`
  (сгенерирована программно; для витрины лучше заказать арт у дизайнера).
- **Обложка/скриншоты** — снимите прямо из игры (лобби, расстановка, бой).
- **Описание** — например: «Тактическая „камень-ножницы-бумага“: скрытые фигуры,
  ловушки и захват флага. 20 ИИ-противников, Башня и PvP-арена с рейтингом MMR».
- **Возрастное ограничение** — 0+ / 6+ (насилия нет).
- **Ссылка на поддержку** — ваша почта или группа VK.

После заполнения отправьте на модерацию и по одобрении переключите приложение
в состояние «Видно всем».

## Как это устроено технически (справка)

- VK открывает `https://rps-battles.com/` в iframe и добавляет к URL параметры
  запуска: `vk_user_id`, `vk_app_id`, `vk_language`, … и подпись `sign`.
- Клиент (`client/App.js`) видит `vk_user_id`+`sign`, вызывает
  `vkBridge.send('VKWebAppInit')` (обязательное «приложение готово» для VK),
  запрашивает имя/аватар через `VKWebAppGetUserInfo` (не обязательно) и шлёт все
  параметры запуска POST-ом на `/api/v2/auth/vk`.
- Бэкенд (`backend/src/controllers/auth.js → verifyVKSign`) собирает
  отсортированные `vk_*`-параметры в строку `key=encodeURIComponent(value)&…`,
  считает HMAC-SHA256 с `VK_APP_SECRET`, кодирует base64url и сравнивает с `sign`
  (плюс сверяет `vk_app_id` с `VK_APP_ID`). При успехе находит/создаёт
  пользователя `platform='vk', externalId=vk_user_id` и выдаёт JWT-токены —
  дальше игра работает одинаково для всех платформ.
- Язык интерфейса берётся из `vk_language`.

## Диагностика

| Симптом | Причина / решение |
|---|---|
| Пустой/серый экран в VK | Проверьте заголовок: `curl -skI https://rps-battles.com/ \| grep -i security` — должен содержать `frame-ancestors … vk.com …`. Конфиг: `/etc/nginx/sites-available/rps-battles.com`. |
| Показывается экран входа вместо автологина | В URL iframe нет `vk_user_id`/`sign` (открыли сайт напрямую, не через VK) — это нормально для обычного веба. Внутри VK: проверьте, что адрес iframe в настройках — именно `https://rps-battles.com/`. |
| Ошибка 401 `Invalid VK Mini App signature` | Неверный `VK_APP_SECRET` (взяли сервисный ключ вместо защищённого) или ключ от другого приложения. |
| Ошибка 401 `VK app id mismatch` | `VK_APP_ID` в `.env` не совпадает с ID приложения, из которого открыта игра. |
| Логи бэкенда | `journalctl -u rps-v2-backend -f` |

## Прицел на будущее (другие платформы)

Сервер и база одни на всех, аккаунты различаются полем `platform`:

- **Яндекс Игры**: `cd client && npm run build:yandex` → архив `rps-battle-yandex.zip`,
  ключ в `YANDEX_APP_SECRET` (см. RELEASE.md §5).
- **Facebook Instant**: `npm run build:fb` → `rps-battle-fb.zip`, ключ в `FB_APP_SECRET` (RELEASE.md §4).
- **iOS/Android**: EAS Build, гостевой вход по deviceId (RELEASE.md §6).

Заголовок `frame-ancestors` в nginx сейчас разрешает только VK: Яндекс и FB
хостят сборку у себя, им iframe на наш домен не нужен.
